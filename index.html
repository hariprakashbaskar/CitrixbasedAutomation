Executive Summary

A lightweight architecture that keeps automation development and test assets on the local machine while executing UI actions inside the Citrix Windows session.

Core Design Principle
The automation framework, test scripts, Page Objects and locator repository remain on the local QA workstation. Only a lightweight execution agent is deployed inside the Citrix session.
01

One-Time Citrix Setup

Deploy a lightweight agent executable inside the Citrix environment. The complete automation framework does not need to be installed there.

02

Real UIA Locators

Use PyWinAuto with the UIA backend to inspect actual Windows controls instead of relying on coordinates, screenshots, OCR or image recognition.

03

Local Development

Locator files, Page Objects, PyTest scenarios, test data and reports remain within the local automation project.

Current Challenge

Why traditional local desktop automation cannot directly inspect a Citrix-hosted application.

L

Local Machine

The QA workstation primarily receives the Citrix presentation/ICA stream. The local operating system does not necessarily have direct access to the actual TradeEngine Windows control tree.

C

Citrix Session

TradeEngine and its Windows controls actually execute inside the remote Windows session. Therefore UIA inspection must happen within that session.

Target Architecture

Separate development from remote UI execution.

Local Page Object Model

Locators are separated from business scenarios. 

class SearchPage:

    SEARCH_BOX = {
        "automation_id": "txtSearch",
        "control_type": "Edit"
    }

    SEARCH_BUTTON = {
        "automation_id": "btnSearch",
        "control_type": "Button"
    }


    def enter_search(self, value):

        self.agent.type(
            locator=self.SEARCH_BOX,
            value=value
        )


    def click_search(self):

        self.agent.click(
            locator=self.SEARCH_BUTTON
        )

PyTest Execution

Test scenarios remain completely readable and business-focused. 

def test_search_trade():

    search_page.enter_search("ABC123")

    search_page.click_search()

    result = search_page.get_result()

    assert result == "FILLED"
Important: The PyTest process remains on the local machine. The actual interaction with TradeEngine is executed inside the Citrix interactive session by the lightweight agent.

End-to-End Execution Flow

STEP 01

Open TradeEngine

User opens TradeEngine inside the Citrix session.

STEP 02

Capture UIA Locator

Locator Inspector requests information from agent.exe and PyWinAuto inspects the UIA tree.

STEP 03

Save Locator Locally

The locator is normalized and stored in the local JSON repository.

STEP 04

Develop Page Object

Page classes consume the locator definitions.

STEP 05

Run PyTest

Test execution starts from the local workstation.

STEP 06

Execute Inside Citrix

Agent.exe resolves the locator and performs the UI action through PyWinAuto/UIA.

STEP 07

Return Result

Execution status and retrieved values are returned to the local framework.

STEP 08

Generate Report

HTML or Allure reports are generated locally.

Why UI Automation Instead of Pixel Automation?

Capability UIA / PyWinAuto Pixel / Coordinate
Real control identification Yes No
AutomationId / Name Available when exposed No
Resolution independent Generally No
Screen position dependency Low High
Maintainability High Low
Requires visible UI Usually interactive session Yes

Critical Feasibility Gate

Validate the application before investing in the complete framework.

GO

UIA Controls Are Exposed

PyWinAuto can identify TradeEngine controls and retrieve meaningful properties such as Name, AutomationId, ControlType and ClassName.

NO

UIA Tree Is Not Exposed

If the application does not expose useful UIA metadata, the architecture should not fall back automatically to fragile coordinate automation. Vendor-supported APIs or approved integration mechanisms should be evaluated.
