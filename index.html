TradeEngine Citrix UI Automation

01 — Executive Summary

Automate the real application — not the Citrix pixels

TradeEngine is a third-party Windows application delivered through a Citrix environment. The objective is to automate the application without modifying the vendor application, without installing the complete automation framework inside Citrix, and without relying on screen coordinates, OCR or image matching.

01
One-time Citrix setup

Deploy a small agent.exe inside the interactive Citrix session.

02
Local development

Keep locators, Page Objects, PyTest tests and framework code on the QA machine.

03
Remote UI execution

The agent executes UIA operations against TradeEngine inside Citrix.

04
Local reporting

Test results, logs and reports return to the local automation environment.

Core proposition: The Citrix environment becomes an execution endpoint rather than the automation development environment.
02 — Current State

Why conventional automation struggles with Citrix

When TradeEngine is launched through Citrix, the local machine normally sees the Citrix client/session rather than the underlying Windows control tree of the application.

Pixel / Image Automation

Coordinates, screenshots and OCR attempt to infer what is displayed.

Maintenance Problem

DPI, resolution, window position, themes and session changes can break tests.

Target State

Execute inside the Citrix Windows session and access the real UIA control tree.

03 — Design Principle

Separate automation ownership from application execution

Local Machine = Automation Intelligence

  • Locator Inspector
  • Locator repository
  • Page Object Model
  • PyTest test scenarios
  • Test data
  • Framework utilities
  • Logging
  • HTML / Allure reports
  • CI/CD integration

Citrix Machine = Lightweight Execution Bridge

  • One-time agent installation
  • Bundled Python/UIA runtime
  • PyWinAuto execution
  • UIA control discovery
  • Click / type / read / wait operations
  • JSON request/response
  • No test suite storage required
  • No Page Objects required
  • No reporting framework required
Important technical clarification: The automation framework and source code remain local. However, the actual PyWinAuto/UIA operation must execute inside the Citrix Windows session because that is where the TradeEngine controls exist. The lightweight agent therefore contains the minimum UI automation runtime.
04 — Target Architecture

One-time Citrix agent + local automation framework

The target architecture creates a clean boundary between the QA automation environment and the third-party Citrix application environment.

06 — Local Automation Framework

Locators and test logic remain local

Page Object

class SearchPage:

    SEARCH_BOX = {
        "automation_id": "txtSearch",
        "control_type": "Edit"
    }

    SEARCH_BUTTON = {
        "automation_id": "btnSearch",
        "control_type": "Button"
    }

    def enter_search(self, value):
        self.agent.type(
            locator=self.SEARCH_BOX,
            value=value
        )

    def click_search(self):
        self.agent.click(
            locator=self.SEARCH_BUTTON
        )

PyTest Scenario

def test_tradeengine_search():

    search_page.enter_search(
        "ABC123"
    )

    search_page.click_search()

    result = search_page.get_result()

    assert result == "FILLED"
Developer experience: The QA engineer writes normal Python/Page Object/PyTest automation locally. The test does not need to understand Citrix internals.
07 — Test Execution

Local PyTest → Agent → TradeEngine

The test remains on the local machine. The agent receives only the required automation command and executes it against the real UI inside Citrix.

08 — Lightweight Agent

The Citrix installation should be deliberately small

Recommended Model

Package the required Python runtime, PyWinAuto, UIA integration and REST server into a standalone executable.

Target: agent.exe
  • No full automation repository
  • No PyTest installation required
  • No Page Objects
  • No test data repository
  • No reporting framework
  • No Inspect.exe dependency
  • No OCR engine
  • No coordinate scripts

09 — Deployment Model

One-time Citrix deployment

1. Obtain infrastructure approval

Confirm that a lightweight executable is permitted within the approved interactive Citrix session.

2. Deploy agent.exe

Place the signed/approved agent package on the designated Citrix machine or approved automation location.

3. Configure agent

Configure port, authentication, session binding and logging policy.

4. Start agent in interactive session

The agent must run in the same Windows desktop session as TradeEngine.

5. Validate health endpoint

Local automation environment confirms the agent is reachable.

6. Leave the Citrix environment unchanged

Future test development happens from the local automation repository.

Deployment principle: The third-party TradeEngine installation is not modified. The agent is an external automation bridge operating alongside the application within the Windows session.

11 — Security Architecture

Controlled, least-privilege communication

Area Recommended Control
Network Internal corporate network only
Authentication Token/service authentication for API requests
Authorization Allow only approved automation actions
Session Bind execution to the intended Citrix interactive session
Privileges Run using standard user permissions where possible
Encryption HTTPS where required by enterprise security policy
Audit Log command, timestamp, session and result
Exposure Do not expose agent directly to the public internet

Least Privilege

Agent should not require local administrator privileges unless explicitly required by the infrastructure design.

Restricted Endpoint

Only approved automation clients should be able to invoke the agent.

Auditability

Every remote action can be logged for troubleshooting and compliance.

12 — Automation Strategy

Why UIA is preferred over pixel automation

Characteristic Pixel / Image / OCR UIA Agent
Element targeting Coordinates / image matching AutomationId / Name / ControlType / hierarchy
DPI changes Can break automation Generally independent of screen coordinates
Resolution Highly sensitive Not dependent on screenshot resolution
Application theme Can affect image matching Metadata-based
Maintenance High Lower when stable UIA properties exist
Execution location Usually outside / visual stream Inside target Windows session
Debugging Screenshot analysis Control metadata and structured logs
Important: "Locator-driven" does not mean every application automatically exposes perfect locators. The quality of automation depends on the UIA/accessibility metadata exposed by TradeEngine.

15 — Risks & Mitigations

Key technical risks

Risk Impact Mitigation
TradeEngine does not expose UIA controls High Perform UIA feasibility spike before framework development. Evaluate vendor-supported integration if required.
UIA properties are unstable Medium Use multiple attributes and hierarchical locators instead of relying on one property.
Citrix session unavailable High Use dedicated automation session/service account and approved session policy.
Agent blocked by endpoint security Medium Use signed/package-approved executable and involve infrastructure/security teams early.
Network communication blocked Medium Define an approved internal route and restricted port/firewall rule.
Third-party application changes Medium Centralize locators in Page Objects / JSON repository.

17 — Recommended End State

The final operating model

Recommended Architecture Statement

"Deploy a lightweight automation agent once inside the Citrix interactive session, while keeping locator management, Page Objects, PyTest scenarios, test data, reporting and automation development entirely within the local QA environment."

Lightweight

One packaged agent rather than a complete automation framework inside the third-party Citrix environment.

Maintainable

Locators and test logic remain under normal source-control and QA development practices.

Enterprise Friendly

The vendor application remains unchanged and the automation boundary is clearly isolated through the agent.

Recommended next step: Start with a small UIA feasibility spike on one TradeEngine screen. Confirm that a Search box, button and one result/grid control expose useful UIA properties. Once that gate passes, build the lightweight agent and remote locator workflow before expanding into full regression automation.
